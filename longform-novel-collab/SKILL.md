# Longform Novel Collaboration

Use this skill for ongoing Chinese webnovel or longform fiction work that combines editorial review, chapter drafting, revision, and project-state sync.

This skill assumes the agent is working with a living novel project, not a one-off prompt.

## Core rule

Treat the written chapter as the primary narrative object, but do not let every draft sentence become permanent setting truth until the local project rule or user confirmation allows it.

When this skill overlaps with project-governance skills, use them for file state and sync discipline. Use this skill for prose, chapter shape, evaluation, and next-chapter execution.

## Operating Modes

Identify the mode before acting.

### 1. Start or recover a session

Use when entering a project, resuming after a break, or before writing the next chapter.

Do:

- Load the smallest useful context set.
- Read the current effective outline or canon file.
- Read the latest chapter full text.
- Read adjacent chapter text only when continuity, voice, or local rhythm requires it.
- Confirm the active manuscript layer: draft, revised chapter, formal text, outline, or notes.
- Identify the current chapter number and the next intended chapter.

Avoid:

- Loading the full manuscript by default.
- Treating chat history as the only source of project truth.
- Promoting old outline plans over newer written chapters.

### 2. Evaluate feedback

Use when the user pastes commentary, critique, or chapter evaluation.

Default behavior:

- Treat the feedback as editorial input for the latest chapter.
- Extract what should be kept, what should be adjusted, and what affects future chapters.
- Do not rewrite the chapter unless the user asks or the workflow says critique should trigger revision.
- If the feedback confirms the chapter direction, sync the confirmed points into the current effective outline.
- If the feedback changes future direction, update the next-chapter plan.

Evaluation checks:

- Does the chapter have one main movement?
- What changes from start to finish?
- Does each scene segment do new work?
- Are important characters anchored as people, not fields or labels?
- Is the tension escalating, bending, resolving, or clarifying?
- Does the prose preserve specific texture instead of becoming generic polish?
- Do institutional processes, physical actions, and character knowledge obey what the scene allows?

Use this compact Chinese feedback shape when asked to evaluate:

总体判断：
主要优点：
主要问题：
修改建议：
下一章方向：

### 3. Write or revise a chapter

Use when the user asks to write, continue, rewrite, or apply feedback.

Before drafting:

- Read the latest chapter full text.
- Read the current effective outline section for the current arc.
- Identify the chapter's single main movement.
- Identify the ending pressure or hook before writing.
- Preserve established voice, rhythm, and local motifs.

While drafting:

- Write one complete current chapter only.
- Keep one chapter focused on one main movement.
- Use one small answer plus one new pressure when possible.
- Do not overload the chapter with new terms unless the chapter's function is opening a system.
- Let concrete actions carry rules instead of explaining rules abstractly.
- Use ordinary life details as anchors when the project relies on reality pressure.
- Keep dialogue character-specific.
- Avoid making every character speak like the narrator.
- Avoid polished sameness, symmetrical AI-sounding paragraphs, and repeated rhetorical patterns.
- Avoid overusing generated-tone words such as “仿佛、似乎、某种、无法言说、令人窒息、蔓延、静静地、淡淡地、微微、缓缓、轻轻” unless the sentence truly needs them.

After drafting:

- Save the chapter as a text file if the project is file-based.
- Update the current effective outline if the local project rule says written chapters should be synced.
- Mark or state whether the chapter is drafted, revised, confirmed, and synced.
- Keep future chapter implications as suggestions unless confirmed or already written.

## Style Discipline

Preserve:

- Concrete dialogue.
- Character-specific gestures and habits.
- Messy but meaningful office-life details.
- Emotional restraint where the project style depends on it.
- Repeated motifs that create rhythm or continuity.
- Ordinary objects that carry thematic weight.

Do not flatten:

- A specific cup, badge, plant, paper, meal, door, or text message into “a现实锚点”.
- Character banter into exposition.
- Institutional pressure into generic villainy.
- Unconfirmed suspicion into confirmed setting fact.

## Character Entry Rules

When an important recurring character meaningfully enters:

- Identify their role or work function.
- Show why they matter in this scene.
- Give one concrete behavioral or visual marker.
- Let the viewpoint character's reaction help define the first impression.

Do not let a major character appear only as a name, field, or system label.

## Scene Structure Rules

Each chapter should have functional segments:

- Anchor current pressure.
- Test or complicate one problem.
- Use character action to find a partial solution.
- Leave a changed condition at the end.

Avoid flat repetition:

- If the previous chapter already tested one format or field, the next chapter should shift pressure form, scale, person, or consequence.
- Do not keep adding “system asks another field” unless it changes the human situation.

## Project Sync Rules

When writing in a file-based project:

- Update the chapter file.
- Update the current effective outline or canon file when the round creates stable chapter facts.
- Record next-chapter direction at the end of the relevant outline section.
- Do not silently overwrite older versions unless the user asked.

Useful status labels:

- drafted
- revised
- pending confirmation
- confirmed
- synced
- needs revisit

## Final Response

After writing or revising, be brief.

Include:

- What was done.
- Which chapter file changed.
- Which outline/canon file was synced.
- Any important residual risk or next hook.

Prefer links to local files when available.
